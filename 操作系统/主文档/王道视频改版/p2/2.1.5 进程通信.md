# 进程间通信（IPC）

## 摘要

本笔记系统化解析进程间通信的三种核心机制：**共享存储**（内存管理模块）、**消息传递**（进程管理模块）和**管道通信**（文件系统模块）。通过对比实现原理、系统调用接口和典型代码案例，提供可验证的实验方案与性能优化思路。

---

## 主题

IPC 是突破进程隔离性的关键机制，通过**内存映射** 、**消息队列** 和 **管道缓冲区** 实现数据交换。需重点关注 **同步机制设计** 与 **内核实现差异** 。

> **重点难点**
>
> - 共享存储的原子性保障（自旋锁 vs 信号量）
> - 消息队列的优先级控制与流量整形
> - 管道半双工特性导致的死锁风险

## 线索区

### 知识点 1：[共享存储（内存管理模块）](./WIKI/Shared_Memory.md)

#### 共享内存实现方式

1. **基于存储区**：
   - 创建固定大小的共享内存区域
   - 进程通过系统调用映射到自己的地址空间
   - 示例流程：

     ```mermaid
     graph TD
         A[进程A调用shmget] --> B[内核创建共享内存区]
         B --> C[进程A调用shmat映射]
         C --> D[进程B调用shmat映射同一区域]
     ```

2. **基于数据结构**：
   - 共享特定数据结构而非连续内存区
   - 需要严格同步访问
   - 示例：共享队列、共享哈希表

#### 内存布局与共享流程

1. 申请阶段：

   ```c
   // 进程A创建共享内存
   int shmid = shmget(IPC_PRIVATE, sizeof(SharedData), 0666|IPC_CREAT);
   ```

2. 映射阶段：

   ```c
   // 进程A和进程B分别映射
   SharedData* data = (SharedData*)shmat(shmid, NULL, 0);
   ```

3. 同步机制：
   - 必须使用信号量/互斥锁保护共享数据
   - 示例：

     ```c
     sem_wait(&data->lock);  // 获取锁
     data->value++;          // 修改共享数据  
     sem_post(&data->lock);  // 释放锁
     ```

#### 关键特性对比

| 特性        | 基于存储区          | 基于数据结构       |
|------------|-------------------|------------------|
| 粒度       | 字节级            | 结构体级         |
| 灵活性     | 低               | 高              |
| 同步要求   | 必须              | 必须            |
| 适用场景   | 大数据块传输      | 结构化数据共享   |

- **注意事项**

> - 共享内存段生命周期独立于进程
> - 必须显式调用`shmdt`解除映射
> - 使用`ipcs -m`监控共享内存使用

### 知识点 2：[消息传递（进程管理模块）](./WIKI/Direct_Communication.md)

#### 1. 通信方式对比
| 类型 | 寻址方式 | 耦合度 | 典型实现 | 数据结构支持 |
|------------|-------------------|--------|-----------------|--------------|
| 直接通信 | PID 直连（send/receive） | 高 | UNIX域套接字 | 原始字节流 |
| 间接通信 | 信箱（mq_open） | 低 | POSIX消息队列 | 结构化消息 |
| 管道通信 | 文件描述符 | 中 | 匿名/命名管道 | 字节流 |

#### 2. 原语方式消息处理（直接通信）
```c
// 发送方
send(receiver_pid, &msg, sizeof(msg));

// 接收方 
receive(sender_pid, &msg, sizeof(msg));
```
特点：
- 进程必须明确知道对方PID
- 通信链路自动建立
- 适用于紧密耦合进程

#### 3. 管道通信特性
```mermaid
graph LR
    A[写进程] -->|fd[1]| B[内核缓冲区]
    B -->|fd[0]| C[读进程]
```

关键限制：
1. 半双工通信，双向通信需要两个管道
   ```c
   int fd1[2], fd2[2]; 
   pipe(fd1); // 进程A→进程B
   pipe(fd2); // 进程B→进程A
   ```
2. 必须互斥访问（内核自动实现）
3. 阻塞行为：
   - 写满时写进程阻塞
   - 读空时读进程阻塞
4. 数据消费模型：
   - 单读多写模式（408真题方案）
   - 轮询读取模式（Linux方案）

#### 4. 消息队列示例
```python
# 创建优先级消息队列
mq = posix_ipc.MessageQueue(
    "/priority_q",
    flags=posix_ipc.O_CREAT,
    max_messages=10,
    max_message_size=1024
)

# 发送带优先级的消息
mq.send("Urgent".encode(), priority=2)
mq.send("Normal".encode(), priority=1)
```

### 知识点 3：[管道通信（文件系统模块）](./WIKI/Direct_Communication.md)

> **实现原理**

![img1744092969034](image/2.1.5进程通信/1744092969034.png)

```mermaid
graph LR
    A[写进程] -->|"write(fd[1])"| B[环形缓冲区]
    B -->|"read(fd[0])"| C[读进程]
```

> **关键特性**

- 容量限制：**Linux 默认 64KB**（可通过`fcntl(fd, F_SETPIPE_SZ)`调整）
- 阻塞行为：读空管道时阻塞直到**EPIPE**信号

> **实验验证**

```bash
# 观察管道写满行为
dd if=/dev/zero of=/tmp/mypipe bs=4096 count=16 &
cat /tmp/mypipe | pv -b > /dev/null
```

## 总结区

> **核心考点**

1. 共享内存与信号量的配合使用（生产者-消费者问题）
2. 消息队列的优先级反转解决方案（优先级继承协议）
3. 命名管道 vs 匿名管道的适用场景

> **优化方向**

- 共享存储：采用 **大页内存（HugeTLB）** 降低 TLB miss 率
- 消息传递：使用**零拷贝技术**（splice/sendfile）减少数据移动
- 管道：设置**O_NONBLOCK**标志实现异步 IO

> **真题难点**

- 多进程同时读写共享内存时的 ABA 问题
- 消息队列持久化与内存映射文件的性能对比
- 管道通信在内核中的缓冲区管理算法

> 实验建议：通过`strace -e trace=ipc`追踪 IPC 系统调用序列，结合`perf stat`分析上下文切换开销。
